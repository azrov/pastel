#14. Your first window

Part 1 wrote programs that talk through the terminal. Most people expect a window: buttons, fields, lists. This chapter makes one, explains how a Pastel app is put together, and starts Pocket's app.

#A new app

pastel new app hello
cd hello
pastel run

A window opens with a field and two buttons. Type your name and press Send. In VS Code: Pastel: New Project… → Desktop App, then F9.

The project:

hello/
├── pastel.toml
├── assets/
│   ├── icon.png          the app's icon, everywhere
│   └── theme.toml        its look (chapter 19)
└── src/
    ├── main.pas          starts the app
    └── forms/
        ├── Home.pform    the window's layout
        └── Home.pas      the window's code

Every window — a form — is two files with the same name: a .pform that says what is in it and a .pas that says what it does. This is Delphi's .dfm and .pas, and the same idea as HTML and its script.

#The program

src/main.pas is short and rarely changes:

program hello;

{$mode objfpc}{$H+}

uses
  Pastel.App, Home;

begin
  Application.Initialize;
  Application.CreateForm(THomeForm, HomeForm);
  Application.Run;
end.

Application (from Pastel.App) is the app: Initialize sets it up (fonts, language, theme), CreateForm makes the window from its .pform, and Run shows it and answers the mouse and keyboard until the window is closed. The first form created is the main window.

#The layout: a .pform file

object HomeForm: THomeForm
  Title = 'hello'
  Width = 460
  Height = 340
  Layout = Free
  object Heading: TLabel
    Left = 24
    Top = 24
    Text = 'Hello!'
    FontSize = 22
    Bold = True
  end
  object NameEdit: TEdit
    Left = 24
    Top = 96
    Width = 412
    Anchors = [Left, Top, Right]
    Placeholder = 'Your name'
    OnSubmit = SendClick
  end
  object SendButton: TButton
    Left = 356
    Top = 144
    Width = 80
    Anchors = [Top, Right]
    Text = 'Send'
    OnClick = SendClick
  end
  object Greeting: TLabel
    Left = 24
    Top = 208
    Width = 412
    Anchors = [Left, Top, Right]
    TextAlign = Center
  end
end

(Shortened: the real file has a hint line and a Clear button too.)

  • object Name: TType … end makes a control; objects inside another become its children.
  • The lines set properties — the published properties of the class, which you met in chapter 8. Text in single quotes, numbers plain, True/False, choices by name (TextAlign = Center), sets in brackets.
  • OnClick = SendClick connects an event to a method of the form.
  • Layout = Free places every control where its Left and Top say, as in Delphi. Anchors = [Left, Top, Right] stretches the edit when the window gets wider. (Chapter 15 shows the other way to lay out, which Pocket uses.)

#The code: Home.pas

unit Home;

{$mode objfpc}{$H+}

interface

uses
  SysUtils, Pastel.UI, Pastel.Dialogs, Home.g;

type
  THomeForm = class(THomeFormBase)
    procedure SendClick(Sender: TObject);
    procedure ClearClick(Sender: TObject);
  end;

var
  HomeForm: THomeForm;

implementation

procedure THomeForm.SendClick(Sender: TObject);
begin
  if Trim(NameEdit.Text) = '' then
    Greeting.Text := 'Please type your name first.'
  else
    Greeting.Text := 'Hello, ' + Trim(NameEdit.Text) + '! Welcome to Pastel.';
end;

procedure THomeForm.ClearClick(Sender: TObject);
begin
  NameEdit.Text := '';
  Greeting.Text := '';
  NameEdit.SetFocus;
end;

end.

Where do NameEdit and Greeting come from? From Home.g, a unit Pastel generates from the .pform at every build:

{ Generated by Pastel from Home.pform - do not edit. }
unit Home.g;

type
  THomeFormBase = class(TForm)
  published
    Heading: TLabel;
    NameEdit: TEdit;
    SendButton: TButton;
    Greeting: TLabel;
    ...

THomeForm inherits from THomeFormBase (chapter 8), so every control of the .pform is a field of your form, with the right type. Rename a control in the .pform and the compiler shows every line of code that still uses the old name. The generated code never mixes with yours.

An event handler is a method with the signature the event wants — for a click, procedure X(Sender: TObject), where Sender is the control that was clicked. One handler can serve several controls: OnSubmit of the edit (Enter pressed in it) and OnClick of the button both call SendClick.

#Hot reload

Run the app with pastel run, then change Text = 'Hello!' in Home.pform and save. The window changes at once — no restart, and what you typed stays in the field. A debug build reads the .pform from disk and watches it; a release build has it compiled in.

Changes to the .pas code need a restart: stop and press F9 again, or let pastel run --watch restart the app whenever a file is saved.

#The designer

Open Home.pform in VS Code and press the designer button in the editor's title bar. It is laid out like Delphi: the Structure and Object Inspector (with Properties and Events) on the left, the form in the middle, the Tool Palette on the right. Drag a control from the palette onto the form, change its properties, double-click an event to write its handler. F12 switches between the form and its code.

Every change in the designer is an ordinary edit of the .pform text, and every edit of the text shows in the designer — use whichever is quicker. The designer also shows the form at phone, tablet and desktop sizes, dark, and in each platform's style.

#Pocket's app begins

Make the app next to the library and the command line:

pastel new app pocket-app

and name the library in its pastel.toml, as pocket-cli does:

# Example: Pocket as an app for computers and phones - the program part 2 of
# the handbook (docs/handbook) builds. Try it: pastel run

[project]
name = "pocket-app"
version = "1.0.0"
pastel = "2.1"
title = "Pocket"
description = "What you spend and earn, and where the money goes"
type = "app"

[build]
main = "src/main.pas"
mode = "objfpc"

[targets]
platforms = ["linux", "windows", "android"]

[dependencies]
pocket-core = { path = "../pocket-core" }

[package.android]
id = "dev.pastel.pocket"

platforms lists where it will run: Linux and Windows, and Android from chapter 21. [package.android] id names the app on phones.

The app has two forms: the main window, Home, and a dialog for one entry, EntryEditor. main.pas creates both:

{ Pocket: what you spend and earn, and where the money goes.
  Handbook: part 2, chapters 14 to 22. }
program PocketApp;

{$mode objfpc}{$H+}

uses
  Pastel.App, Home, EntryEditor;

begin
  Application.Initialize;
  Application.CreateForm(THomeForm, HomeForm);
  Application.CreateForm(TEntryForm, EntryForm);
  Application.Run;
end.

The next chapters build them: the layout (chapter 15), the list and the dialog (16), the database (17), the chart and reports (18).

#Exercises

  1. In the hello app, add a TCheckBox Shout and write the greeting in capitals when it is ticked (Upper from Pastel.Text).
  2. Add a second button that counts how many times it was clicked and shows the number in its own Text.
  3. With the app running, change colors and texts in the .pform and watch them change. Then make a mistake in it (delete an end) and save: what does the window show?
  4. ★ Use the designer only: add a TComboBox with three cities and a label that shows the chosen one (its OnChange event).
