#17. A database

Chapter 11 kept Pocket's entries in a JSON file: read everything when the program starts, write everything when it changes. That is fine for a hundred entries. An app that is changed every day, by a click here and a delete there, wants a database: it writes only what changed, it cannot be left half-written when the battery dies, and it finds the rows you ask for without reading the rest.

#SQL in one page

A relational database keeps tables: rows with the same columns, like a sheet. You talk to it in SQL, a language of its own:

create table entries (id integer primary key, day varchar(10), category varchar(100), amount decimal(14,2));
insert into entries (day, category, amount) values ('2026-11-03', 'Food', 12.50);
select category, amount from entries where day >= '2026-11-01' order by amount desc;
update entries set amount = 13 where id = 1;
delete from entries where id = 1;

primary key makes id the row's number, given by the database. where chooses rows, order by sorts them. Dates as YYYY-MM-DD text sort in the right order — the reason Pocket stores them that way.

#Pastel.Db

Pastel.Db speaks to SQLite (a database in one file, nothing to install), PostgreSQL and MySQL with the same code. A TDatabase is opened from an address:

program Ledger;

{$mode objfpc}{$H+}

uses
  SysUtils, fpjson, Pastel.Db, Pastel.Json;

var
  Db: TDatabase;
  Rows: TJSONArray;
  I: Integer;
  Id: Int64;
begin
  Db := TDatabase.Open('sqlite::memory:');      // in memory; 'sqlite:pocket.db' is a file
  try
    Db.Exec('create table entries (id integer primary key, day varchar(10), ' +
      'category varchar(100), amount decimal(14,2))', []);
    Db.Insert('insert into entries (day, category, amount) values (?, ?, ?)', ['2026-11-03', 'Food', 12.5]);
    Db.Insert('insert into entries (day, category, amount) values (?, ?, ?)', ['2026-11-04', 'Rent', 650]);
    Id := Db.Insert('insert into entries (day, category, amount) values (?, ?, ?)', ['2026-11-04', 'Food', 8.2]);
    WriteLn('The last entry got the id ', Id);

    Rows := Db.Query('select category, sum(amount) as total from entries group by category order by total desc', []);
    try
      for I := 0 to Rows.Count - 1 do
        WriteLn(Format('%-6s %8.2f', [JStr(Rows.Items[I], 'category'), JFloat(Rows.Items[I], 'total')]));
    finally
      Rows.Free;
    end;

    WriteLn('Entries for food: ', Db.QueryInt('select count(*) from entries where category = ?', ['Food'], 0));
    WriteLn('Changed: ', Db.Exec('update entries set amount = amount + 1 where category = ?', ['Food']));
  finally
    Db.Free;
  end;
end.

The last entry got the id 3
Rent     650.00
Food      20.70
Entries for food: 2
Changed: 2
Db.Exec(SQL, [values]) create, update, delete: the number of rows changed
Db.Insert(SQL, [values]) an insert: the new row's id
Db.Query(SQL, [values]) the rows, as a TJSONArray of objects (chapter 11) — you free it
Db.QueryOne(SQL, [values]) the first row, or nil
Db.QueryInt, Db.QueryValue the first column of the first row, as a number or a text

#Values go in as ?

Never build SQL with +:

Db.Exec('delete from entries where category = ''' + Name + '''', []);   // NO
Db.Exec('delete from entries where category = ?', [Name]);              // yes

If Name came from a field and someone typed x' or '1'='1, the first line deletes every row. With ? the value is sent apart from the SQL and is only ever a value. This mistake — SQL injection — is one of the most common security holes there is; ? rules it out.

#Pocket's store in a database

Chapter 13 made IEntryStore an interface so that the place the entries are kept can change. Here is the third store, built on a database:

{ The entries in a database (SQLite in the app; PostgreSQL or MySQL work the
  same). One more IEntryStore: the code that uses a store does not change.

    Store := TDbStore.Create('sqlite:' + JoinPath([DataDir, 'pocket.db']));
    Store.Load(Entries);

  Besides Load and Save (everything at once) it keeps one entry at a time:
  Put (new or changed) and Remove - what an app does after every edit.

  Handbook: chapter 17 (databases). }
unit PocketDbStore;

{$mode objfpc}{$H+}

interface

uses
  SysUtils, Pastel.Db, PocketEntries, PocketStore;

type
  TDbStore = class(TInterfacedObject, IEntryStore)
  private
    FDb: TDatabase;
  public
    { 'sqlite:pocket.db', 'sqlite::memory:', 'postgres://...'; the table is made when missing. }
    constructor Create(const Url: string);
    destructor Destroy; override;
    procedure Load(Entries: TEntryList);
    procedure Save(Entries: TEntryList);
    function Where: string;
    { One entry: a new one (Id 0) gets its id; a changed one is written over. }
    procedure Put(E: TEntry);
    procedure Remove(AId: Int64);
    property Db: TDatabase read FDb;
  end;

implementation

uses
  fpjson, Pastel.Json;

constructor TDbStore.Create(const Url: string);
begin
  inherited Create;
  FDb := TDatabase.Open(Url);
  FDb.Exec('create table if not exists entries (' +
    'id integer primary key, ' +
    'day varchar(10) not null, ' +
    'kind varchar(10) not null, ' +
    'category varchar(100) not null, ' +
    'amount decimal(14,2) not null, ' +
    'note varchar(500) not null default '''')', []);
end;

destructor TDbStore.Destroy;
begin
  FDb.Free;
  inherited Destroy;
end;

function TDbStore.Where: string;
begin
  Result := FDb.SafeUrl;
end;

procedure TDbStore.Load(Entries: TEntryList);
var
  Rows: TJSONArray;
  Row: TJSONData;
  Kind: TEntryKind;
  E: TEntry;
  I: Integer;
begin
  Entries.Clear;
  Rows := FDb.Query('select id, day, kind, category, amount, note from entries order by day desc, id desc', []);
  try
    for I := 0 to Rows.Count - 1 do
    begin
      Row := Rows.Items[I];
      TryParseKind(JStr(Row, 'kind'), Kind);
      E := Entries.AddEntry(IsoToDate(JStr(Row, 'day')), Kind, JStr(Row, 'category'),
        JFloat(Row, 'amount'), JStr(Row, 'note'));
      E.Id := JInt(Row, 'id');
    end;
  finally
    Rows.Free;
  end;
end;

procedure PutIn(S: TDbSession; E: TEntry);
begin
  if E.Id = 0 then
    E.Id := S.Insert('insert into entries (day, kind, category, amount, note) values (?, ?, ?, ?, ?)',
      [DateToIso(E.Date), KindName(E.Kind), E.Category, Double(E.Amount), E.Note])
  else if S.Exec('update entries set day = ?, kind = ?, category = ?, amount = ?, note = ? where id = ?',
    [DateToIso(E.Date), KindName(E.Kind), E.Category, Double(E.Amount), E.Note, E.Id]) = 0 then
    { an id from somewhere else (a JSON file): kept with it }
    S.Exec('insert into entries (id, day, kind, category, amount, note) values (?, ?, ?, ?, ?, ?)',
      [E.Id, DateToIso(E.Date), KindName(E.Kind), E.Category, Double(E.Amount), E.Note]);
end;

procedure TDbStore.Put(E: TEntry);
begin
  PutIn(FDb, E);
end;

procedure TDbStore.Remove(AId: Int64);
begin
  FDb.Exec('delete from entries where id = ?', [AId]);
end;

procedure TDbStore.Save(Entries: TEntryList);
var
  Tx: TDbTransaction;
  E: TEntry;
begin
  { all or nothing: a failure halfway leaves the table as it was }
  Tx := FDb.BeginTransaction;
  try
    Tx.Exec('delete from entries', []);
    for E in Entries do
    begin
      if E.Id <> 0 then
        Tx.Exec('insert into entries (id, day, kind, category, amount, note) values (?, ?, ?, ?, ?, ?)',
          [E.Id, DateToIso(E.Date), KindName(E.Kind), E.Category, Double(E.Amount), E.Note])
      else
        PutIn(Tx, E);
    end;
    Tx.Commit;
  finally
    Tx.Free;
  end;
end;

end.

Points to look at:

  • The table is made when missing (create table if not exists), so a new app on a new phone starts with an empty table. A bigger app uses migrations — numbered SQL files run once each, in order (database.md).
  • Load reads the rows back as JSON, with JStr, JFloat and JInt from chapter 11.
  • Put writes one entry: an insert for a new one, which gives it its id, an update for a changed one. The app calls it after every edit, so nothing is lost if the app is closed or killed.
  • Save uses a transaction: everything between BeginTransaction and Commit happens together or not at all. If writing the 500th entry fails, the finally frees the transaction without Commit and the table is as it was — never half old and half new.
  • PutIn takes a TDbSession: both TDatabase and TDbTransaction are one, so the same code writes inside a transaction or outside it.

Because it is an IEntryStore, pocket-cli could use it with no change but one line — try exercise 1.

#Where the file lives

The app must keep its database where it may write, and where the user's files are not:

{ Where the entries are kept: POCKET_DB, or pocket.db in the app's own folder. }
function DatabaseUrl: string;

implementation

uses
  DateUtils, Pastel.Env, Pastel.Lang, Pastel.Device, Pastel.Print, Pastel.Report, Pastel.Sheets, Pastel.Workers,
  PocketReports, PocketStore, PocketImport, EntryEditor;

type
  { what the import in the background needs, and what it leaves for ImportDone }
  TImportJob = class
    FileName: string;
    Entries: TEntryList;       { the file's entries; given to the main list in ImportDone }
    constructor Create(const AFileName: string);
    destructor Destroy; override;
  end;

constructor TImportJob.Create(const AFileName: string);
begin
  inherited Create;
  FileName := AFileName;
  Entries := TEntryList.Create;
end;

GetAppConfigDir is the app's own folder — ~/.config/pocket-app on Linux, AppData\Local\pocket-app on Windows. An Android app has a private folder of its own and starts in it, so a plain name is enough there. {$IFDEF ANDROID} compiles a part only for one platform; use it sparingly, for the few places where platforms really differ.

The environment variable POCKET_DB overrides the place. The app's tests use it to start with a database of their own — sqlite::memory: or a file in a temporary folder — and never touch the real one.

#Exercises

  1. Give pocket-cli a --db option: with it, the command line keeps its entries in a TDbStore instead of the JSON file.
  2. Write a select that gives the month's expenses by category straight from the database (group by, where day like '2026-11-%'). Compare it with TotalsByCategory.
  3. Try the delete with + from above on a table of your own, with the evil name. Then with ?.
