#Appendix B. Coming from Delphi or Lazarus

Most of what you know carries over: the language is the same Object Pascal, a form is still a layout file and a unit, events are still methods with a Sender. This appendix lists what is different, so you can skip the chapters you do not need.

#The language: {$mode objfpc} and {$mode delphi}

Free Pascal speaks several dialects. This book uses {$mode objfpc}; {$mode delphi} is closer to what Delphi accepts. A project chooses in pastel.toml:

[build]
mode = "delphi"

and a unit can say it in its first lines. Units of both modes work together in one program.

{$mode objfpc} {$mode delphi} (and Delphi)
Generic types generic TBox<T> = class / specialize TList<Integer> TBox<T> = class / TList<Integer>
An event handler Button.OnClick := @SaveClick; Button.OnClick := SaveClick;
Result always there always there
string with {$H+}: a long string, UTF-8 {$H+} is on
Several routines of one name overload optional overload needed 
program FromDelphi;

{$mode delphi}

uses
  SysUtils, Generics.Collections;

type
  TBox<T> = class
    Value: T;
    constructor Create(AValue: T);
  end;

constructor TBox<T>.Create(AValue: T);
begin
  Value := AValue;
end;

var
  Names: TList<string>;
  Box: TBox<Integer>;
  S: string;
begin
  Names := TList<string>.Create;
  Box := TBox<Integer>.Create(42);
  try
    Names.Add('Ayşe');
    Names.Add('Mehmet');
    for S in Names do
      WriteLn(S);
    WriteLn(Box.Value);
  finally
    Box.Free;
    Names.Free;
  end;
end.

Ayşe
Mehmet
42

#Strings

Delphi's string is UTF-16 (UnicodeString); Free Pascal's, with {$H+}, is UTF-8 (AnsiString with the UTF-8 code page). For most code this does not matter. Where it does: Length('ş') is 2 (bytes, not letters), and S[I] is a byte. Chapter 6 shows the helpers for letters (Pastel.Text). Code that reads files is simpler: files are UTF-8 too.

#What Free Pascal has and Delphi has not (or the other way)

  • Free Pascal only: generic/specialize, operators overloaded outside a type (operator + (A, B: TMoney): TMoney;), {$modeswitch ...} for single features (advancedrecords for methods in records), for..in over an enumeration type.
  • Delphi only (not in Free Pascal 3.2): inline variables (var X := 5; inside a block) and anonymous methods — use a method of the form instead; attributes are limited.
  • Round rounds a half to the even number in both; Pastel's money code adds 0.5 and truncates (chapter 4).

#Forms: .dfm and .pform

A .pform is a .dfm in text form, with a few names changed:

Delphi (VCL / FMX) Pastel
Caption of a form Title
Caption of a button, label, check box Text
Align = alTop / alClient Dock = Top / Fill (in a Layout = Free parent)
Anchors = [akLeft, akTop, akRight] Anchors = [Left, Top, Right]
Font.Size, Font.Style = [fsBold] FontSize, Bold = True
TPageControl + TTabSheet TTabControl + TTabSheet (Caption stays)
TStringGrid, TDBGrid TGrid with TGridColumn children
TMainMenu, TPopupMenu, TActionList TMenuBar, TPopupMenu, TAction
TDateTimePicker, TSpinEdit, TTrackBar TDatePicker, TNumberEdit, TSlider
TPanel, TGroupBox, TTimer, TImage the same names

What is new:

  • Flow layout (chapter 15): TRow, TColumn, Grow, Gap. Delphi has TFlowPanel and TGridPanel; here it is the normal way, and what makes a form fit a phone.
  • The generated unit: the controls are declared in Home.g.pas, made from the .pform at every build, and your form inherits from it (chapter 14). Your .pas holds only your code.
  • Hot reload: a saved .pform changes the running app.
  • One look everywhere: Pastel draws its controls itself — no native widgets — and style = "auto" gives each platform its look (chapter 19), like FireMonkey's styles.

pastel check tells you about properties a control does not have, so a Caption left on a button is found at once.

#Dialogs that do not wait

ShowModal, ShowMessage, MessageDlg and the file dialogs wait, as in the VCL. Each also has a form that returns at once and calls a method with the result (chapter 16) — what FireMonkey asks for on Android (ShowModal(procedure (ModalResult: TModalResult) ...)). Use that form in code that should run on phones:

EntryForm.ShowModal(@EntryDone);            // objfpc; in delphi mode: EntryForm.ShowModal(EntryDone)

#The IDE and the project

Delphi Pastel
The IDE VS Code with Pastel's extension: designer, Object Inspector, Tool Palette, F9, F12, breakpoints
.dproj pastel.toml (a few lines of text)
Target Platforms the platform box in the status bar; pastel build --target windows
Packages (.bpl), GetIt libraries in [dependencies] (chapter 12), pastel add
Deployment pastel package (chapter 22)

Everything the IDE does is also a pastel command, so a build server does exactly what F9 does.

#Lazarus

Lazarus uses the same compiler, so its non-visual code — units with SysUtils, Classes, fpjson, sqldb — compiles in a Pastel project as it is. The LCL's forms (.lfm) are close to Delphi's and differ from .pform in the same ways as above.
