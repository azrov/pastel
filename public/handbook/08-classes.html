#8. Classes and objects

A record keeps data together. A class keeps data together with the code that works on it, and decides which parts the rest of the program may touch. Classes are the "Object" in Object Pascal; forms, controls, lists, database connections — nearly everything in Pastel is one.

#A first class

program Accounts;

{$mode objfpc}{$H+}

uses
  SysUtils;

type
  TAccount = class
  private
    FOwner: string;
    FBalance: Currency;
  public
    constructor Create(const AOwner: string);
    procedure Deposit(Amount: Currency);
    function Withdraw(Amount: Currency): Boolean;
    property Owner: string read FOwner;
    property Balance: Currency read FBalance;
  end;

constructor TAccount.Create(const AOwner: string);
begin
  inherited Create;
  FOwner := AOwner;
  FBalance := 0;
end;

procedure TAccount.Deposit(Amount: Currency);
begin
  FBalance := FBalance + Amount;
end;

function TAccount.Withdraw(Amount: Currency): Boolean;
begin
  Result := Amount <= FBalance;
  if Result then
    FBalance := FBalance - Amount;
end;

var
  A: TAccount;
begin
  A := TAccount.Create('Ada');
  try
    A.Deposit(100);
    if not A.Withdraw(150) then
      WriteLn('Not enough money.');
    A.Withdraw(30);
    WriteLn(A.Owner, ' has ', CurrToStr(A.Balance), '.');
  finally
    A.Free;
  end;
end.

Not enough money.
Ada has 70.

Step by step:

  • Fields hold the data. By custom their names start with F.
  • Methods are the routines of the class, declared in it and written below with the class name in front: TAccount.Deposit. Inside a method, the fields of the object are just there — FBalance.
  • private parts are for the class's own code. public parts are for everyone. The balance is private and only readable through the Balance property: nobody can set it to a million by mistake; money only moves through Deposit and Withdraw, which keep it correct.
  • The constructor Create makes an object and sets it up; inherited Create lets the parent class (here the root of all classes, TObject) do its part first.

#Objects live until you free them

TAccount.Create(...) makes a new object in memory and gives back a reference to it. The variable A holds that reference, not the object itself. Pascal has no garbage collector: an object stays in memory until it is freed, so every Create needs a Free.

The pattern that never forgets:

A := TAccount.Create('Ada');
try
  // use A
finally
  A.Free;
end;

try … finally runs the finally part whatever happens in the try part — even when an error (chapter 9) jumps out of it. Write the try right after the Create, and the Free before anything else.

To find a forgotten Free, let Free Pascal count: with these lines in pastel.toml, a debug build lists at its end every piece of memory that was not freed, and where it was made:

[profile.debug]
options = ["-gh"]

#References, not copies

Because variables hold references, assigning one object variable to another does not copy the object:

program References;

{$mode objfpc}{$H+}

type
  TBox = class
    Value: Integer;
  end;

var
  A, B: TBox;
begin
  A := TBox.Create;
  try
    A.Value := 1;
    B := A;                        // the same object, a second name for it
    B.Value := 2;
    WriteLn('A.Value = ', A.Value);
    WriteLn('Same object? ', A = B);
  finally
    A.Free;                        // once: there is only one object
  end;
end.

A.Value = 2
Same object? TRUE

Compare this with records (chapter 5), where assignment copied everything. After A.Free, B points to freed memory: using it is a bug. A variable that points to nothing holds nil; Assigned(A) asks whether it is not nil, and FreeAndNil(A) frees and sets it to nil in one step.

(TBox has a public field without private: fine for a tiny example; real classes keep their fields private.)

#Properties

A property looks like a field from outside, but the class decides what reading and writing it does. It can read a field directly and write through a method that checks the value:

property Amount: Currency read FAmount write SetAmount;

procedure TEntry.SetAmount(AValue: Currency);
begin
  if AValue < 0 then
    raise EArgumentException.Create('an amount is never negative');
  FAmount := AValue;
end;

Now E.Amount := -5 cannot happen without an error. Properties can also be computed — read GetBalance calls a function — or read-only, with no write at all.

#Inheritance

A class can be built on another: it inherits all of the parent's fields, methods and properties, adds its own, and can change how inherited methods behave:

program Shapes;

{$mode objfpc}{$H+}

uses
  SysUtils;

type
  TShape = class
  public
    function Area: Double; virtual; abstract;
    function Describe: string; virtual;
  end;

  TCircle = class(TShape)
  private
    FRadius: Double;
  public
    constructor Create(ARadius: Double);
    function Area: Double; override;
    function Describe: string; override;
  end;

  TRectangle = class(TShape)
  private
    FWidth, FHeight: Double;
  public
    constructor Create(AWidth, AHeight: Double);
    function Area: Double; override;
  end;

function TShape.Describe: string;
begin
  Result := Format('%s with an area of %.2f', [ClassName, Area]);
end;

constructor TCircle.Create(ARadius: Double);
begin
  inherited Create;
  FRadius := ARadius;
end;

function TCircle.Area: Double;
begin
  Result := Pi * FRadius * FRadius;
end;

function TCircle.Describe: string;
begin
  Result := inherited Describe + Format(' (radius %.1f)', [FRadius]);
end;

constructor TRectangle.Create(AWidth, AHeight: Double);
begin
  inherited Create;
  FWidth := AWidth;
  FHeight := AHeight;
end;

function TRectangle.Area: Double;
begin
  Result := FWidth * FHeight;
end;

var
  List: array of TShape;
  S: TShape;
  Total: Double;
begin
  List := [TCircle.Create(1), TRectangle.Create(2, 3), TCircle.Create(0.5)];
  Total := 0;
  for S in List do
  begin
    WriteLn(S.Describe);
    Total := Total + S.Area;
    if S is TCircle then
      WriteLn('  (a round one)');
  end;
  WriteLn(Format('Together: %.2f', [Total]));
  for S in List do
    S.Free;
end.

TCircle with an area of 3.14 (radius 1.0)
  (a round one)
TRectangle with an area of 6.00
TCircle with an area of 0.79 (radius 0.5)
  (a round one)
Together: 9.93
  • class(TShape) makes TCircle a kind of TShape. A variable of type TShape can hold any shape.
  • virtual methods can be replaced by child classes with override; the object's real class decides which one runs. S.Describe on a circle runs TCircle.Describe even though S is a TShape — this is polymorphism: one loop handles every kind of shape.
  • abstract says the parent has no code for it; every child must give one. (Creating a TShape itself would be a mistake, and calling its Area an error.)
  • inherited Describe calls the parent's version from inside the child's.
  • is asks whether an object is of a class (or a child of it); as converts the reference, with an error if it is not: (S as TCircle).
  • ClassName is the class's name, a method every object has from TObject.

#Destructors

When a class owns other objects, it frees them in its destructor, which always looks like this:

destructor TReport.Destroy;
begin
  FLines.Free;               // what this object made
  inherited Destroy;         // then the parent's part
end;

declared in the class as destructor Destroy; override;. Never call Destroy yourself — call Free, which calls Destroy and does nothing when the reference is nil.

#In Pocket: an entry as an object

Chapter 5 kept an entry in a record. As a class, it can protect its amount (never negative) and answer questions about itself (SignedAmount: negative for an expense). This is Pocket's TEntry, here inside a small program; chapter 10 puts it in its unit next to the list of entries:

program EntryObject;

{$mode objfpc}{$H+}

uses
  SysUtils;

type
  TEntryKind = (ekExpense, ekIncome);

  { One expense or income. }
  TEntry = class
  private
    FId: Int64;
    FDate: TDateTime;
    FKind: TEntryKind;
    FCategory: string;
    FAmount: Currency;
    FNote: string;
    procedure SetAmount(AValue: Currency);
  public
    { The amount with its sign: an expense is negative. }
    function SignedAmount: Currency;
    property Id: Int64 read FId write FId;
    property Date: TDateTime read FDate write FDate;
    property Kind: TEntryKind read FKind write FKind;
    property Category: string read FCategory write FCategory;
    { Always positive; EArgumentException otherwise. }
    property Amount: Currency read FAmount write SetAmount;
    property Note: string read FNote write FNote;
  end;

procedure TEntry.SetAmount(AValue: Currency);
begin
  if AValue < 0 then
    raise EArgumentException.CreateFmt('an amount is never negative (%s): the kind says expense or income',
      [CurrToStr(AValue)]);
  FAmount := AValue;
end;

function TEntry.SignedAmount: Currency;
begin
  if FKind = ekExpense then
    Result := -FAmount
  else
    Result := FAmount;
end;

var
  E: TEntry;
begin
  E := TEntry.Create;
  try
    E.Date := EncodeDate(2026, 11, 3);
    E.Kind := ekExpense;
    E.Category := 'Food';
    E.Amount := 12.50;
    E.Note := 'Lunch';
    WriteLn(FormatDateTime('yyyy-mm-dd', E.Date), ' ', E.Category, ' ', CurrToStr(E.SignedAmount));
  finally
    E.Free;
  end;
end.

2026-11-03 Food -12.5

TEntry needs no constructor of its own: TObject.Create is enough, and every field of a new object starts at zero, '' or False. Id is 0 until something that keeps entries (chapter 11) gives it a number.

#Exercises

  1. Give TAccount a property History: string that lists every deposit and withdrawal, one per line.
  2. Add a TSquare to the shapes, as a child of TRectangle with one size. Which methods does it need?
  3. Write a class TCounter with Increment, Reset and a read-only Value. Create two counters and show that they are separate.
  4. ★ Add options = ["-gh"] under [profile.debug] in pastel.toml, remove a Free from one of the programs and run it. Read what it says about the memory at the end.
