#7. Units

A program in one file is fine for a page of code. Beyond that, it gets hard to find things, and code that would be useful elsewhere is stuck inside it. Pascal splits programs into units: files of related types and routines, each with a public part and a private part. This chapter shows how units work — and starts Pocket for real.

#A unit

unit Greetings;

{$mode objfpc}{$H+}

interface

{ What other units and programs may use. }
function Greet(const Name: string): string;

implementation

uses
  SysUtils;

{ Only this unit sees it. }
function Polite(const Name: string): string;
begin
  if Name = '' then
    Result := 'friend'
  else
    Result := Name;
end;

function Greet(const Name: string): string;
begin
  Result := Format('Hello, %s!', [Polite(Name)]);
end;

end.

A unit has two parts:

  • interface — the declarations other code may use: types, constants, variables, and the first line of each public routine. It is the unit's promise to the rest of the program.
  • implementation — the code of those routines, and anything else the unit needs only for itself (Polite here: nobody outside can call it).

The unit ends with end. The file is named after the unit, in lower case: greetings.pas.

A program (or another unit) names the unit in its uses clause, and from then on can use what its interface offers:

program UseGreetings;

{$mode objfpc}{$H+}

uses
  Greetings;

begin
  WriteLn(Greet('Ada'));
  WriteLn(Greet(''));
end.

Hello, Ada!
Hello, friend!

#Two uses clauses

A unit can have a uses clause in each part. Units needed by the interface (a type used in a public declaration) go in the first; units needed only by the code go in the implementation one. Keep the first short: everything it names becomes a dependency of everyone who uses your unit.

Two units may not use each other in their interface parts — Pascal needs to know one before the other. When two units really need each other, one of them names the other in its implementation's uses.

#Names from two units

When two units offer the same name, the unit named later in uses wins. To pick one, write the unit's name before it: SysUtils.Format(...), Greetings.Greet(...).

#initialization and finalization

A unit may end with code that runs once when the program starts, and once when it ends:

unit Counter;

{$mode objfpc}{$H+}

interface

var
  Calls: Integer;

procedure Count;

implementation

procedure Count;
begin
  Inc(Calls);
end;

initialization
  Calls := 0;
  WriteLn('(Counter is ready)');

end.

program UseCounter;

{$mode objfpc}{$H+}

uses
  Counter;

begin
  WriteLn('Working...');
  Count;
  Count;
  WriteLn('Count was called ', Calls, ' times.');
end.

(Counter is ready)
Working...
Count was called 2 times.

The initialization of every unit runs before the program's begin, in the order of the uses clauses. A finalization section, after it, runs when the program ends — the place to free what the initialization made (chapter 8 shows freeing). By then the screen may already be closed, so do not write to it there.

Use them sparingly: code that runs "by itself" is easy to forget about.

#Where units live in a Pastel project

Pastel finds the units of a project by itself: every .pas file in src/ and its sub-folders. There is no list to keep up to date — make a file, name the unit in uses, and build. A common layout:

src/
├── main.pas            the program
├── forms/              windows (part 2)
├── models/             the data
└── services/           the work: files, network, calculations

The folders are for people; to the compiler a unit is a unit, wherever it is.

pastel new also gives every project a unit you do not see: AppInfo, made from pastel.toml at every build. AppName and AppVersion in it always match the project file.

#Pocket begins

Time to start the real program. Make a project:

pastel new console pocket
cd pocket

Pocket's first unit is everything about money as text: writing an amount (FormatMoney, chapter 4) and reading one (TryParseMoney, chapter 6). Make src/pocketmoney.pas:

{ Money as text and back: amounts are Currency (exact to 4 decimal places,
  no rounding surprises like 0.1 + 0.2 with Double).

    FormatMoney(1234.5)            -> '1,234.50'
    TryParseMoney('12,5', Amount)  -> True, Amount = 12.5

  Handbook: chapter 2 (types), chapter 6 (strings). }
unit PocketMoney;

{$mode objfpc}{$H+}

interface

{ 1234.5 -> '1,234.50': a comma between thousands, a dot before the cents. }
function FormatMoney(Amount: Currency): string;

{ An amount typed by a person: '12', '12.5', '12,50', '1,234.50', '1.234,50'.
  The last dot or comma with one or two digits after it starts the cents;
  others only group thousands. False when it is not an amount. }
function TryParseMoney(const Text: string; out Amount: Currency): Boolean;

implementation

uses
  SysUtils;

function FormatMoney(Amount: Currency): string;
var
  Whole, Cents: Int64;
  Digits: string;
  I, Count: Integer;
  Negative: Boolean;
begin
  Negative := Amount < 0;
  if Negative then
    Amount := -Amount;
  { Currency keeps 4 decimal places: to cents, a half cent up (Round would
    take it to the even number: Round(0.5) = 0) }
  Cents := Trunc(Amount * 100 + 0.5);
  Whole := Cents div 100;
  Cents := Cents mod 100;
  Digits := IntToStr(Whole);
  { a comma before every group of three digits, from the right }
  Result := '';
  Count := 0;
  for I := Length(Digits) downto 1 do
  begin
    if (Count > 0) and (Count mod 3 = 0) then
      Result := ',' + Result;
    Result := Digits[I] + Result;
    Inc(Count);
  end;
  Result := Result + '.' + Format('%.2d', [Cents]);
  if Negative then
    Result := '-' + Result;
end;

function TryParseMoney(const Text: string; out Amount: Currency): Boolean;
var
  S, Clean: string;
  I, DecimalAt: Integer;
  Negative: Boolean;
  FS: TFormatSettings;
begin
  Amount := 0;
  S := Trim(Text);
  Negative := (S <> '') and (S[1] = '-');
  if Negative then
    Delete(S, 1, 1);
  if S = '' then
    Exit(False);
  { where the cents start: the last separator with one or two digits after it }
  DecimalAt := 0;
  for I := Length(S) downto 1 do
    if S[I] in ['.', ','] then
    begin
      if Length(S) - I <= 2 then
        DecimalAt := I;
      Break;
    end;
  Clean := '';
  for I := 1 to Length(S) do
    if S[I] in ['0'..'9'] then
      Clean := Clean + S[I]
    else if I = DecimalAt then
      Clean := Clean + '.'
    else if not (S[I] in ['.', ',', ' ']) then
      Exit(False);            { a letter or another sign: not an amount }
  if (Clean = '') or (Clean = '.') then
    Exit(False);
  { a dot, whatever the computer's language writes }
  FS := DefaultFormatSettings;
  FS.DecimalSeparator := '.';
  Result := TryStrToCurr(Clean, Amount, FS);
  if Result and Negative then
    Amount := -Amount;
end;

end.

Some things are new since the versions in chapters 4 and 6:

  • The comment at the top says what the unit is for, with an example. Write one for every unit: it is the first thing a reader sees.
  • The interface has only the two routines and a comment for each — the contract. How they do it is in the implementation, which a user of the unit never needs to read.
  • FormatMoney handles negative amounts: it remembers the sign, works on the positive amount, and puts the minus back at the end.

Now src/main.pas uses it:

program PocketTry;

{$mode objfpc}{$H+}

uses
  PocketMoney;

var
  Amount, Total: Currency;
  Line: string;
begin
  Total := 0;
  repeat
    Write('Amount (empty to stop): ');
    ReadLn(Line);
    if Line = '' then
      Break;
    if TryParseMoney(Line, Amount) then
      Total := Total + Amount
    else
      WriteLn('  "', Line, '" is not an amount.');
  until False;
  WriteLn('Total: ', FormatMoney(Total));
end.

12.50
1.234,50
lunch
-4

Amount (empty to stop): Amount (empty to stop): Amount (empty to stop):   "lunch" is not an amount.
Amount (empty to stop): Amount (empty to stop): Total: 1,243.00

repeat … until False loops forever; the Break inside is the way out. (An empty input — the line after -4 — ends it.)

The program is short because the details live in the unit. That is the point: main.pas says what happens, the units say how.

#Exercises

  1. Move the Week program's day names (chapter 5) into a unit Days with a function DayName(Day: Integer): string, and use it from a program.
  2. Give PocketMoney a function FormatMoneyWith(Amount: Currency; const Symbol: string): string that writes '12.50 €'. Use FormatMoney inside it.
  3. What happens when a program uses a unit that is not in src/? Read the compiler's message.
