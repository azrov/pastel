#22. Shipping

Pocket runs on your computer. This last chapter gets it onto other people's: a release build, a package for each platform, a key for Android, and a way to update.

#Before a release

pastel fmt                # the code in one shape
pastel check              # the forms, the project, the texts
pastel test               # pocket-core's tests
pastel lang               # nothing left untranslated

A UI script drives the app like a user — clicks, typing, what the window shows — with no screen, so it runs on a build server too:

POCKET_DB=sqlite::memory: PASTEL_HEADLESS=1 PASTEL_TEST_SCRIPT=tests/ui.txt ./build/linux/debug/pocket-app

(POCKET_DB, chapter 17: the test never touches your real entries.)

Pocket's is examples/pocket-app/tests/ui.txt; forms.md has the commands it may use.

Then raise the version in pastel.toml — 1.0.0 to 1.0.1 for fixes, 1.1.0 for something new, 2.0.0 when old data or habits no longer fit. The program can show it: the AppVersion constant of the generated unit AppInfo is always the version of pastel.toml.

#Release builds

pastel build --release

A release build is optimized, smaller, and has no debugger information and no hot reload: its forms are compiled into it. It is what every pastel package below builds and packs.

#A package for each platform
pastel package a .tar.gz (Linux) or .zip (Windows) with the program and its files
pastel package deb a Debian/Ubuntu/Mint package, with a menu entry and the icon
pastel package appimage one file that runs on most Linux systems
pastel package installer --target windows a Windows installer (setup.exe, needs makensis), with a Start menu entry and an uninstaller
pastel package apk an Android app for every kind of processor, to install by hand
pastel package aab the bundle Google Play wants

All of them can be made on Linux: the Windows program is built there too (--target windows). pastel package --all makes one for every platform of pastel.toml. Everything lands in dist/, each file with a .sha256 next to it — a fingerprint, for anyone who wants to check that the file is the one you made.

The name under the icon is [project] title (Pocket), the icon assets/icon.png, in every size each platform needs.

#Android: the key

Android knows an app by the key it was signed with. A debug key is made for you; for a release, make your own, once:

pastel keystore                                        # keys/upload.keystore; asks for a password
PASTEL_KEYSTORE_PASSWORD=... pastel package aab        # dist/pocket-app-1.0.0.aab, signed

Every update must be signed with the same key. Keep a copy of the file and its password away from the computer. Lose them, and the app cannot be updated: it would be a new app, and every user would have to start again. keys/ is in .gitignore, so the key never lands in a public repository.

Upload the .aab in Google Play's console. What Play asks of new apps — made for the newest Android, 16 KB memory pages, the icon in the phone's shape — Pastel does by itself (android.md).

#Updating itself

An app from Google Play is updated by Play. One you hand out yourself can look for a new version:

uses
  Pastel.Updater, AppInfo;

procedure THomeForm.CheckWork(Sender: TObject);        { in the background: the network (chapter 20) }
var
  Update: TUpdateInfo;
begin
  if CheckForUpdate('https://example.com/pocket/update.json', AppVersion, Update) then
    ...
end;

pastel update-manifest https://example.com/pocket/ "What is new" writes dist/update.json from the packages in dist/; put it and them at that address. The installer, the AppImage and the .apk each know how to replace themselves (system.md).

#What you built

Pocket is three projects, and every part of the book is in them:

pocket-core/     types, classes, lists, files, JSON, a database, the bank import — and their tests
pocket-cli/      the command line: interfaces, arguments, tables in the terminal
pocket-app/      the app: forms, layouts, a grid, a dialog, a chart, reports, threads, languages, phones

The code you read in these chapters is the code of those folders — the book is checked against it on every change of Pastel, so it cannot drift.

#Where next

  • The manual: docs/ has a page for every part of Pastel; this book left out much more than it showed — a web server and API (web.md), sign-in (auth.md), sync that works offline (sync.md), services (services.md).
  • The examples: examples/ has an app for a hair salon with invoices and its server, a notepad, a contacts app, a weather app, a duplicate-file finder and an API for notes. Read them like this book: start at main.pas, then the forms.
  • Delphi and Lazarus code: Appendix B shows what is the same and what is not.
  • Free Pascal itself: its reference guide (freepascal.org/docs) is the final word on the language.

And write a program of your own — the one you need. That is how everyone who programs learned it.

#Exercises

  1. Make a release of Pocket for Linux and Windows, and install it on another computer (or a virtual one).
  2. Show the version in the window's title: Title := 'Pocket ' + AppVersion.
  3. Make a release .apk signed with your own key and install it next to the debug one. What does the phone say?
  4. ★ Put an update.json and a newer package on a local web server (python3 -m http.server), and let the app find it.
