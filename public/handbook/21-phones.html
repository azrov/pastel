#21. Phones

Pocket is most useful in a pocket: the coffee is written down when it is paid, not in the evening. This chapter puts the same app — the same .pform files, the same code — on Android phones.

#Setting up, once

Android apps are built on Linux. Install the tools and let Pastel set up the compilers:

sudo apt install fpc fpc-source binutils-aarch64-linux-gnu binutils-arm-linux-gnueabi binutils-x86-64-linux-gnu
sudo apt install aapt zipalign apksigner android-sdk-platform-23 default-jdk-headless adb
pastel doctor --install android

With Android Studio installed, its SDK is used as well. pastel doctor then shows the kinds of phone it can build for; android.md has the details.

Target For
android-arm64 most phones since about 2016
android-arm older phones, TV boxes
android-x86_64 the emulator and Waydroid on a PC

#Running it

Pocket's pastel.toml (chapter 14) already lists android in its platforms. Connect a phone with USB debugging on (Settings → About phone, tap Build number seven times, then Developer options → USB debugging), and:

pastel run --target android

Pastel asks the phone which processor it has, builds for it, packs and installs a debug .apk, starts it and shows its log until Ctrl+C. Hot reload works here too: save a .pform and the phone changes.

No phone at hand? Waydroid runs Android in a window on Linux; connect adb to it (adb connect with the address waydroid status shows) and pastel run --target android finds it like a phone. Android Studio's emulator works the same way.

In VS Code, choose android in the status bar's platform box; then F9 does all of the above.

#What changes on a phone — and what does not

Pocket needs few changes, because part 2 kept to a few rules:

  • The layout flows (chapter 15). The form fills the screen whatever its size, and ScreenChange hides the chart and the notes column when the screen is a phone's.
  • Dialogs do not wait (chapter 16). ShowModal(@EntryDone) and Ask(…, @DeleteAnswered) work on a phone as on a computer.
  • Slow work is in the background (chapter 20). Android kills an app that does not answer for five seconds.
  • Texts and numbers follow the phone's language (chapter 19), and Appearance = System its dark mode.
  • The style is Material on Android (style = "auto"): round buttons, outlined fields, and the dialogs' buttons in Android's order.

Taps are clicks, holding a finger is a right click, lists scroll with a swipe. The on-screen keyboard comes up for an edit, and the kind it shows follows the control: TCurrencyEdit brings the number keys with a decimal point. The Back button closes the dialog on top, and on the main form the app.

#Where the files go

Two places in Pocket know they may be on a phone. The database (chapter 17): an Android app starts in a private folder of its own, which stays when the app is updated:

{$IFDEF ANDROID}
Result := 'pocket.db';                     { the app's own folder on a phone }
{$ELSE}

And the exports (chapter 18). A phone has no Save as dialog where a user picks a folder; phone apps hand files to other apps instead — mail, Drive, a messenger — through the share menu:

if IsMobile then
  ShareFile(FileName)
else
  OpenDocument(FileName);

IsMobile (from Pastel.Device) is true on phones and tablets. Prefer it to {$IFDEF ANDROID}: it is decided while the app runs, so the same code is right on whatever phone platform comes next.

Pastel.Device has more of what phones offer: the camera and photos, the location, notifications, vibration, the contacts and calendar, sharing into the app — see device.md.

#When the phone stops the app

An app that is not on the screen can be stopped by Android to free memory. When the user comes back, it starts again, and Pastel puts back what the controls showed — the text of edits, the selected row, the scroll position. What is not in a control, the form keeps itself in OnSaveState:

procedure THomeForm.FormSaveState(Sender: TObject);
begin
  SaveState.Values['month'] := Format('%d-%d', [FYear, FMonth]);
end;

and reads back in OnCreate. Pocket's data is in the database after every change (FStore.Put), so nothing is lost — which is the reason it writes at once and not when the app closes: on a phone an app is often never "closed".

#When it crashes

pastel logcat

shows the app's lines of the phone's log, and where a crash in the Pascal code happened (file and line, from the debug build). In VS Code: Pastel: Android Log.

#An .apk to share

pastel package apk

makes dist/pocket-app-1.0.0.apk with every kind of processor in it. Copy it to a phone or a TV box and open it (allow installing from this source once). Chapter 22 makes a release for Google Play.

#Exercises

  1. Run Pocket on a phone, Waydroid or the emulator. Add an entry, turn the phone, and see the layout follow.
  2. Keep the month shown in OnSaveState and read it back in OnCreate, as above. Test it with Developer options → Don't keep activities.
  3. Make the amount field the first one with the focus when the dialog opens on a phone, so the keyboard comes up at once. (Is it already?)
  4. ★ Give the app a home-screen shortcut Add an entry that opens the dialog straight away (SetAppShortcuts, device.md).
