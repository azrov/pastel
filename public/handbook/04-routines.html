#4. Procedures and functions

As a program grows, the same steps come back in several places, and the main block gets long. Procedures and functions give a group of statements a name: you write it once and call it wherever it is needed. Together they are called routines.

#A procedure

program Lines;

{$mode objfpc}{$H+}

procedure Rule;
begin
  WriteLn('----------------------');
end;

begin
  Rule;
  WriteLn('  Pocket, November');
  Rule;
end.

----------------------
  Pocket, November
----------------------

A routine is declared before the begin of the program, after the var and const sections — and before the code that calls it: Pascal reads from top to bottom.

#Parameters

Values given to a routine are its parameters; they are declared in brackets with their types:

program Params;

{$mode objfpc}{$H+}

procedure Rule(Width: Integer; Ch: Char);
var
  I: Integer;
begin
  for I := 1 to Width do
    Write(Ch);
  WriteLn;
end;

procedure Title(const Text: string);
begin
  Rule(Length(Text) + 4, '=');
  WriteLn('  ', Text);
  Rule(Length(Text) + 4, '=');
end;

begin
  Title('Monthly report');
  Rule(10, '.');
end.

==================
  Monthly report
==================
..........

I is a local variable of Rule: it exists while Rule runs and nobody else sees it. Each call has its own.

#A function

A function gives back a value. Inside it, Result is that value:

program Functions;

{$mode objfpc}{$H+}

uses
  SysUtils;

function Square(X: Integer): Integer;
begin
  Result := X * X;
end;

function WithVat(Net: Currency; Rate: Integer): Currency;
begin
  Result := Net + Net * Rate / 100;
end;

function IsEven(N: Integer): Boolean;
begin
  Result := N mod 2 = 0;
end;

begin
  WriteLn('7 squared: ', Square(7));
  WriteLn('250 with 20% VAT: ', CurrToStr(WithVat(250, 20)));
  WriteLn('Is 10 even? ', IsEven(10));
  WriteLn(Square(Square(3)));
end.

7 squared: 49
250 with 20% VAT: 300
Is 10 even? TRUE
81

A function call is a value, so it can stand wherever a value of its type can — in WriteLn, in a sum, inside another call.

#Exit

Exit leaves a routine at once. In a function, Exit(Value) sets Result and leaves — handy for the simple cases first:

program Signs;

{$mode objfpc}{$H+}

function Sign(N: Integer): string;
begin
  if N = 0 then
    Exit('zero');
  if N < 0 then
    Exit('negative');
  Result := 'positive';
end;

begin
  WriteLn(Sign(-4), ' ', Sign(0), ' ', Sign(12));
end.

negative zero positive

#How parameters are passed

Written The routine gets Use it for
X: Integer a copy; changing it changes only the copy small values the routine may change for itself
const X: string the value, which it may not change strings, records, arrays: no copy is made — faster
var X: Integer the caller's variable itself giving back more than one value, changing the caller's
out X: Integer the caller's variable, to fill answers only (its old value is not looked at) 
program Passing;

{$mode objfpc}{$H+}

procedure Twice(X: Integer);
begin
  X := X * 2;                      // only the copy
end;

procedure TwiceVar(var X: Integer);
begin
  X := X * 2;                      // the caller's variable
end;

procedure Split(Total: Integer; out Euros, Cents: Integer);
begin
  Euros := Total div 100;
  Cents := Total mod 100;
end;

var
  N, E, C: Integer;
begin
  N := 5;
  Twice(N);
  WriteLn('After Twice: ', N);
  TwiceVar(N);
  WriteLn('After TwiceVar: ', N);
  Split(1275, E, C);
  WriteLn('1275 cents: ', E, ' and ', C);
end.

After Twice: 5
After TwiceVar: 10
1275 cents: 12 and 75

A var or out parameter needs a variable when called: TwiceVar(5) does not compile (5 is not a place that can change). Use const for strings you only read — it is the habit of Pascal programmers, and of Pastel's own code.

The TryStrToInt(S, N) you met in chapter 2 is such a function: it gives back True or False, and the number through its out parameter.

#Default values

A parameter with a default may be left out when calling:

program Defaults;

{$mode objfpc}{$H+}

procedure Rule(Width: Integer = 20; Ch: Char = '-');
var
  I: Integer;
begin
  for I := 1 to Width do
    Write(Ch);
  WriteLn;
end;

begin
  Rule;
  Rule(5);
  Rule(5, '*');
end.

--------------------
-----
*****

Parameters with defaults come last.

#Overloading

Several routines can share a name when their parameters differ; the compiler picks the one that fits:

program Overloads;

{$mode objfpc}{$H+}

uses
  SysUtils;

function Describe(N: Integer): string; overload;
begin
  Result := 'the number ' + IntToStr(N);
end;

function Describe(const S: string): string; overload;
begin
  Result := 'the text "' + S + '"';
end;

function Describe(B: Boolean): string; overload;
begin
  Result := 'the truth value ' + BoolToStr(B, 'yes', 'no');
end;

begin
  WriteLn(Describe(42));
  WriteLn(Describe('hello'));
  WriteLn(Describe(True));
end.

the number 42
the text "hello"
the truth value yes

(overload is optional in {$mode objfpc}; it is needed in {$mode delphi}, so writing it keeps code portable.)

#Routines inside routines

A routine can have routines of its own, declared before its begin. They see its parameters and local variables, and nobody else sees them:

program Nested;

{$mode objfpc}{$H+}

uses
  SysUtils;

procedure Receipt(const Items: string; Total: Currency);

  procedure Line(const Name: string; Value: Currency);
  begin
    WriteLn(Format('%-10s %8.2f', [Name, Double(Value)]));
  end;

begin
  WriteLn('Receipt for ', Items);
  Line('Net', Total / 1.2);
  Line('VAT', Total - Total / 1.2);
  Line('Total', Total);
end;

begin
  Receipt('2 coffees', 9);
end.

Receipt for 2 coffees
Net            7.50
VAT            1.50
Total          9.00

#A routine that calls itself

A function may call itself — recursion. Each call has its own parameters, and one case must stop it:

program Recursion;

{$mode objfpc}{$H+}

function Factorial(N: Integer): Int64;
begin
  if N <= 1 then
    Result := 1
  else
    Result := N * Factorial(N - 1);
end;

begin
  WriteLn('10! = ', Factorial(10));
  WriteLn('20! = ', Factorial(20));
end.

10! = 3628800
20! = 2432902008176640000

Recursion fits things that are built of smaller things of the same kind: folders in folders, a tree of menu items. For simple counting, a loop is clearer.

#In Pocket

Pocket writes amounts in one way everywhere: two decimals, a comma between thousands — 1,234.50. That is a job for a function. A first version (chapter 6 makes it handle negative amounts too, and chapter 7 moves it into a unit of its own):

program Money;

{$mode objfpc}{$H+}

uses
  SysUtils;

{ 1234.5 -> '1,234.50' }
function FormatMoney(Amount: Currency): string;
var
  Whole, Cents: Int64;
  Digits: string;
  I, Count: Integer;
begin
  Cents := Trunc(Amount * 100 + 0.5);        // to whole cents, a half up
  Whole := Cents div 100;
  Cents := Cents mod 100;
  Digits := IntToStr(Whole);
  Result := '';
  Count := 0;
  for I := Length(Digits) downto 1 do        // from the right: a comma every 3 digits
  begin
    if (Count > 0) and (Count mod 3 = 0) then
      Result := ',' + Result;
    Result := Digits[I] + Result;
    Inc(Count);
  end;
  Result := Result + '.' + Format('%.2d', [Cents]);
end;

begin
  WriteLn(FormatMoney(0));
  WriteLn(FormatMoney(12.5));
  WriteLn(FormatMoney(1234.5));
  WriteLn(FormatMoney(1000000));
end.

0.00
12.50
1,234.50
1,000,000.00

Why not Round? Chapter 2 showed that Round rounds a half to the even number: half a cent would sometimes go up and sometimes down. Adding 0.5 and cutting the rest (Trunc) always goes up. %.2d writes a whole number with at least two digits: 5 becomes 05.

  2. Write procedure Swap(var A, B: Integer) that exchanges two variables.
