#15. Layout

A window is not always the size you designed it for. People make it wider, a laptop has a small screen, a phone is narrow and tall. This chapter shows how Pastel places controls so that a form fits every size — and builds Pocket's main window.

#Two ways to place controls

Free (Layout = Free, chapter 14's hello): every control has a Left, Top, Width, Height, as in Delphi. Anchors decide which edges follow the window when it is resized. Quick to design by dragging, good for dialogs of a fixed size.

Flow (the default when Layout is not set): controls are placed one after another — under each other in a column, side by side in a row — and share the room there is. Nothing has to be placed by hand, and the form follows any size. This is how web pages and phone apps lay out, and how Pocket does it.

#Rows and columns

object Form1: TForm1
  Padding = 16                 // room inside the edges
  Gap = 12                     // room between the children
  object Title: TLabel
    Text = 'Settings'
  end
  object NameRow: TRow         // side by side
    Gap = 8
    Align = Center             // in the middle of the row's height
    object NameLabel: TLabel
      Text = 'Name'
      Width = 80
    end
    object NameEdit: TEdit
      Grow = 1                 // takes the rest of the row
    end
  end
  object Notes: TMemo
    Grow = 1                   // takes the rest of the form's height
  end
  object Buttons: TRow
    Gap = 8
    Justify = End              // at the right end
    object CancelButton: TButton
      Text = 'Cancel'
    end
    object OkButton: TButton
      Text = 'OK'
    end
  end
end

A form is a column. Its children go down, one under the other; TRow puts its children side by side.
TColumn, TRow children under each other / side by side
TFlow side by side, going on to the next line when the row is full (buttons, tags)
TCard a column with a background, a border and round corners
TPanel a box with Layout = Free inside a flow layout
TSpacer empty room that pushes the controls after it away (Grow = 1)
TScrollBox a column that scrolls when its content is taller

And the properties that do the work:
Grow takes the free room: in a column the height, in a row the width. 2 takes twice what 1 does
Width, Height a fixed size; 0 (not set) is "as big as the content needs"
Gap room between children
Padding room inside the container's edges
Align across: Stretch (the default: full width in a column), Start, Center, End
Justify along: Start, Center, End, SpaceBetween
MinWidth, MinHeight (a form) the smallest the window may get
MaxContentWidth the children at most this wide, in the middle: readable on a big screen

Read it from the top: a header row (the arrows around the month, which Grow = 1 pushes to the edges), a row of three cards that share the width (each Grow = 1), the main row that takes all the height left (Grow = 1 in the form) with the list growing beside a chart of a fixed width, and a TFlow of buttons that wraps onto a second line when the window is narrow.

Not one Left or Top: the same file fits a big monitor and a small phone.

#Windows of every size

A wide window has room for the chart beside the list; a phone does not. Every form knows what kind of screen it is on — its ScreenClass: scPhone, scTablet, scTV or scDesktop (a computer's window narrower than 600 counts as a phone, so you can try phone layouts by making the window narrow). OnScreenClassChange runs when the form first shows, and whenever the kind changes:

{ a phone: no room for the chart beside the list, nor for the notes in it }
procedure THomeForm.ScreenChange(Sender: TObject);
var
  Phone: Boolean;
begin
  Phone := ScreenClass = scPhone;
  Spending.Visible := not Phone;
  NoteColumn.Visible := not Phone;
  if Phone then
  begin
    DateColumn.Width := 100;
    CategoryColumn.Width := 0;      { 0: what is left }
  end
  else
  begin
    DateColumn.Width := 110;
    CategoryColumn.Width := 130;
  end;
end;

It is connected in the .pform (OnScreenClassChange = ScreenChange). On a phone the chart and the notes column go, and the date and category columns share what is left; on a computer they come back.

For bigger differences, a form can have views: Home.phone.pform with only the values that differ on phones (sizes, Visible, texts) — see forms.md.

#Checking a layout

pastel check lays out every form at its size and warns when something cannot fit — a row whose controls need more room than there is, so the last ones would be cut off — and about unknown properties. The designer outlines the same problems on the form. And pastel preview draws a form into a picture without running the app:

pastel preview src/forms/Home.pform -o home.png --width 380 --height 720

#Exercises

  1. Make a form with a TMemo that fills it and a row of three buttons at the bottom, right-aligned.
  2. Put two TCards side by side, the first twice as wide as the second (Grow = 2 and Grow = 1).
  3. Make Pocket's window narrow while it runs and watch ScreenChange work. Then hide the Import button on phones too.
  4. ★ Give the header's month label a TComboBox neighbour that chooses the year, but only on desktops.
