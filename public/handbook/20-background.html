#20. Work in the background

Most banks give a month of a bank account as a CSV file. Pocket can read one and add its rows as entries. A month is quick; ten years of a business account is not, and a file on a network drive may take seconds just to open. While the code reads, the window cannot redraw or answer a click — it freezes, and the system offers to kill it.

The cure is to do slow work on another thread, and leave the main thread free for the window.

#The bank import

First the work itself, in pocket-core — plain code with no window in it, so the command line and the tests can use it too:

{ Entries from a bank's CSV file (most banks give one for a month):

    Date;Description;Amount
    03.11.2026;MARKET LUNCH;-47,50
    01.11.2026;SALARY NOVEMBER;3000,00

  The columns are found by their names (date, description or text or note,
  amount or sum, and category when there is one), in any order and case; the
  separator (, ; or tab) is guessed. A negative amount is an expense.

    Count := ImportCsv('november.csv', NewEntries);

  It reads a file and nothing else: an app may run it in the background
  (handbook chapter 20). }
unit PocketImport;

{$mode objfpc}{$H+}

interface

uses
  SysUtils, PocketEntries;

type
  EImportError = class(Exception);

{ Adds the file's rows to Into; returns how many. EImportError (with the line)
  when a needed column is missing or a value is wrong. }
function ImportCsv(const FileName: string; Into: TEntryList): Integer;

{ '2026-11-03', '03.11.2026', '03/11/2026' -> the day; False when not a date. }
function TryParseDay(const S: string; out Day: TDateTime): Boolean;

implementation

uses
  Pastel.Sheets, PocketMoney;

function TryParseDay(const S: string; out Day: TDateTime): Boolean;
var
  T: string;
  Y, M, D: Integer;
begin
  T := Trim(S);
  Result := False;
  Day := 0;
  if Length(T) <> 10 then
    Exit;
  if (T[5] = '-') and (T[8] = '-') then          { 2026-11-03 }
    Result := TryStrToInt(Copy(T, 1, 4), Y) and TryStrToInt(Copy(T, 6, 2), M) and TryStrToInt(Copy(T, 9, 2), D)
  else if (T[3] in ['.', '/']) and (T[6] = T[3]) then    { 03.11.2026, 03/11/2026: the day first }
    Result := TryStrToInt(Copy(T, 1, 2), D) and TryStrToInt(Copy(T, 4, 2), M) and TryStrToInt(Copy(T, 7, 4), Y);
  Result := Result and TryEncodeDate(Y, M, D, Day);
end;

{ the column with one of the names; -1 when there is none }
function ColumnOf(const Heads: array of string; const Names: array of string): Integer;
var
  I: Integer;
  N: string;
begin
  for I := 0 to High(Heads) do
    for N in Names do
      if SameText(Trim(Heads[I]), N) then
        Exit(I);
  Result := -1;
end;

function ImportCsv(const FileName: string; Into: TEntryList): Integer;
var
  Rows: TSheetRows;
  DateCol, TextCol, AmountCol, CategoryCol, I: Integer;
  Day: TDateTime;
  Amount: Currency;
  Kind: TEntryKind;
  Category: string;

  function Cell(Row, Col: Integer): string;
  begin
    if (Col >= 0) and (Col < Length(Rows[Row])) then
      Result := Trim(Rows[Row][Col])
    else
      Result := '';
  end;

begin
  Result := 0;
  try
    Rows := ReadCsv(FileName);
  except
    on E: Exception do
      raise EImportError.CreateFmt('%s cannot be read: %s', [FileName, E.Message]);
  end;
  if Length(Rows) = 0 then
    Exit;
  DateCol := ColumnOf(Rows[0], ['date', 'day']);
  TextCol := ColumnOf(Rows[0], ['description', 'text', 'note', 'details']);
  AmountCol := ColumnOf(Rows[0], ['amount', 'sum', 'value']);
  CategoryCol := ColumnOf(Rows[0], ['category']);
  if (DateCol < 0) or (AmountCol < 0) then
    raise EImportError.CreateFmt('%s: the first line names the columns; Date and Amount are needed', [FileName]);
  for I := 1 to High(Rows) do
  begin
    if (Length(Rows[I]) = 0) or ((Length(Rows[I]) = 1) and (Trim(Rows[I][0]) = '')) then
      Continue;                                  { an empty line }
    if not TryParseDay(Cell(I, DateCol), Day) then
      raise EImportError.CreateFmt('line %d: "%s" is not a date', [I + 1, Cell(I, DateCol)]);
    if not TryParseMoney(Cell(I, AmountCol), Amount) or (Amount = 0) then
      raise EImportError.CreateFmt('line %d: "%s" is not an amount', [I + 1, Cell(I, AmountCol)]);
    if Amount < 0 then
      Kind := ekExpense
    else
      Kind := ekIncome;
    Category := Cell(I, CategoryCol);
    if Category = '' then
      Category := 'Imported';
    Into.AddEntry(Day, Kind, Category, Abs(Amount), Cell(I, TextCol));
    Inc(Result);
  end;
end;

end.

It uses what part 1 taught: ReadCsv from Pastel.Sheets gives the rows as arrays of strings; the columns are found by their names in the first row, so the order does not matter; and every bad line raises an EImportError that says which line and why (chapter 9). A file like this one is read:

Date;Description;Amount
04.12.2026;MARKET;-20,00
01.12.2026;SALARY;3000

#Threads

A program starts with one thread, the main one. A TThread runs its Execute method next to it, at the same time:

program Threads;

{$mode objfpc}{$H+}

uses
  {$IFDEF UNIX}cthreads,{$ENDIF} Classes, SysUtils;

type
  TSumThread = class(TThread)
  private
    FFrom, FTo: Int64;
  protected
    procedure Execute; override;
  public
    Sum: Int64;
    constructor Create(AFrom, ATo: Int64);
  end;

constructor TSumThread.Create(AFrom, ATo: Int64);
begin
  FFrom := AFrom;
  FTo := ATo;
  inherited Create(False);        // False: starts at once
end;

procedure TSumThread.Execute;
var
  I: Int64;
begin
  Sum := 0;
  for I := FFrom to FTo do
    Inc(Sum, I);
end;

var
  A, B: TSumThread;
begin
  A := TSumThread.Create(1, 50000000);
  B := TSumThread.Create(50000001, 100000000);
  A.WaitFor;                      // until A's Execute ended
  B.WaitFor;
  WriteLn('1 + 2 + ... + 100000000 = ', A.Sum + B.Sum);
  A.Free;
  B.Free;
end.

1 + 2 + ... + 100000000 = 5000000050000000

Two halves, summed at the same time on two cores. cthreads gives Linux and macOS programs their threads; it comes first in uses. (pastel build adds it to every project for you — it matters when you compile with plain fpc.)

#The rules

Threads share the program's memory, and that is what makes them hard. Two threads that change the same list at the same moment break it — not every time, only sometimes, which is worse. So:

  1. A thread works on its own data. Give it what it needs before it starts; let it leave its results where only it writes.
  2. Controls belong to the main thread. Never change a label, a grid or a form from another thread.
  3. The main thread takes the results when the thread has finished.

Threads that must share something use a lock (TCriticalSection) or a queue (TMessageQueue from Pastel.Workers); an app rarely needs either.

#RunInBackground

Pastel.Workers makes the rules easy in an app. RunInBackground(@Work, @Done, Data):

  • runs Work on a thread of its own,
  • then Done on the main thread, where controls may be changed,
  • and gives both the same Data object, which carries what the work needs and what it found.

An exception in Work does not end the program: its message is in the task's Error, for Done to show.

Pocket's Import button chooses a file, then hands it to the background:

procedure THomeForm.ImportClick(Sender: TObject);
begin
  OpenFileDialog('', 'CSV|*.csv', _('Import a bank statement'), @ImportChosen);
end;

procedure THomeForm.ImportChosen(Sender: TObject; Ok: Boolean; const FileName: string);
begin
  if not Ok then
    Exit;
  ImportButton.Enabled := False;
  RunInBackground(@ImportWork, @ImportDone, TImportJob.Create(FileName));
end;

The job object carries the file's name in and the entries out:

constructor TImportJob.Create(const AFileName: string);
begin
  inherited Create;
  FileName := AFileName;
  Entries := TEntryList.Create;
end;

destructor TImportJob.Destroy;
begin
  Entries.Free;
  inherited Destroy;
end;

The work touches nothing but the job — not FEntries, not a control:

{ a thread of its own: only the job's data here - no controls, not FEntries }
procedure THomeForm.ImportWork(Sender: TObject);
var
  Job: TImportJob;
begin
  Job := TImportJob(TBackgroundTask(Sender).Data);
  ImportCsv(Job.FileName, Job.Entries);         { an exception becomes the task's Error }
end;

Done runs on the main thread, so it may do everything else: put the entries in the list and the database, show the month, tell the user.

{ the main thread again: the entries into the list and the database }
procedure THomeForm.ImportDone(Sender: TObject);
var
  Task: TBackgroundTask;
  Job: TImportJob;
  E: TEntry;
begin
  Task := TBackgroundTask(Sender);
  Job := TImportJob(Task.Data);
  try
    ImportButton.Enabled := True;
    if Task.Error <> '' then
    begin
      ShowMessage(Task.Error, _('Import'));
      Exit;
    end;
    Job.Entries.OwnsObjects := False;           { they move to FEntries }
    for E in Job.Entries do
    begin
      FEntries.Add(E);
      FStore.Put(E);
    end;
    if Job.Entries.Count > 0 then
    begin
      FYear := YearOf(Job.Entries[0].Date);
      FMonth := MonthOf(Job.Entries[0].Date);
    end;
    ShowMonth;
    ShowToast(Format(_('%d entries imported'), [Job.Entries.Count]));
  finally
    Job.Free;
  end;
end;

Who owns what, once more (chapter 10): the job's list owns the entries it read. They move into FEntries, so the job must stop owning them before it is freed — OwnsObjects := False — or freeing the job would free entries that FEntries still holds. And Done frees the job: the task leaves its Data to Done.

Meanwhile the Import button is disabled, so a second click cannot start a second import of the same file; it comes back in Done, whether the import worked or not.

#Downloading

The same pattern fits everything slow: a big query, a report of a thousand pages, and above all the network. A download of exchange rates with Pastel.Http would look like this:

procedure THomeForm.RatesWork(Sender: TObject);
begin
  TBackgroundTask(Sender).Data := HttpGetJson('https://example.com/rates.json');
end;

procedure THomeForm.RatesDone(Sender: TObject);
var
  Task: TBackgroundTask;
begin
  Task := TBackgroundTask(Sender);
  try
    if Task.Error <> '' then
      ShowToast(_('No connection: the rates of yesterday are used'))
    else
      UseRates(TJSONObject(Task.Data));
  finally
    Task.Data.Free;
  end;
end;

The network can be slow, or not there at all. Never ask it from the main thread — and plan for the answer that does not come.

#Exercises

  1. Run the import with a file of 100,000 lines (write it with a small program and WriteCsv). Watch the window stay alive. Then call ImportCsv directly in ImportChosen and compare.
  2. Give pocket-cli an import command that uses the same ImportCsv.
  3. Show a TProgressBar while the import runs (set Indeterminate, hide it in Done).
  4. ★ Skip the rows that are already there (the same day, amount and note), and say how many were skipped.
