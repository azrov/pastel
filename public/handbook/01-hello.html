#1. Your first program

In this chapter you write a program, run it, and learn what each of its lines means.

#Pascal, Object Pascal, Free Pascal, Pastel

Pascal was designed in 1970 by Niklaus Wirth to teach programming: its code reads almost like English, and the compiler catches many mistakes before the program ever runs. Turbo Pascal made it fast and popular in the 1980s; Delphi (1995) added objects and visual forms, and the language became Object Pascal. Free Pascal is a free compiler for it that makes programs for Windows, Linux, macOS, Android and more.

Pastel is built on Free Pascal. It adds what a modern program needs — a project file, a command that builds, tests and packages, a library of units for files, JSON, HTTP, databases, and forms that look the same on every platform — so you can write the program and let Pastel deal with the rest.

Programs written in Object Pascal are compiled into machine code: they start at once, run fast, and need nothing installed to run — not even Pastel.

#A project

Open a terminal (or VS Code's: Terminal → New Terminal) and type:

pastel new console hello
cd hello
pastel run

pastel new console made a folder with a small command-line program; pastel run compiled it and ran it. In VS Code, Pastel: New Project… does the same, and F9 runs the project.

The folder holds:

hello/
├── pastel.toml          the project: its name, version, what it is
├── src/
│   ├── main.pas         the program
│   └── services/        units with the program's work (chapter 7)
└── tests/               tests (chapter 12)

For the first chapters you only need src/main.pas. Open it, delete everything, and type this:

program Hello;

{$mode objfpc}{$H+}

begin
  WriteLn('Hello, world!');
end.

Run it with pastel run (or F9):

Hello, world!

#Line by line

program Hello; names the program. The name follows the rules of every name in Pascal: letters, digits and _, starting with a letter. The semicolon ends the line's statement.

{$mode objfpc}{$H+} are compiler directives: settings for the compiler, written as comments that start with $. {$mode objfpc} chooses Free Pascal's object-oriented dialect, the one this book uses. {$H+} makes string a modern string of any length. Put both lines at the top of every program and unit; pastel new does it for you.

begin … end. hold what the program does. The last end of a program has a full stop, not a semicolon: it is the end of the file as far as the compiler cares.

WriteLn('Hello, world!'); writes a line on the screen. Text in Pascal goes between single quotes. To write a quote itself, write it twice: 'It''s fine'.

#Case does not matter

Pascal does not care about upper and lower case: WriteLn, writeln and WRITELN are the same. Pastel's code and this book write names with capitals (WriteLn, PocketMoney) and keywords in lower case (begin, end) — the way most Pascal code looks. pastel fmt puts the keywords right for you.

#Semicolons separate

A semicolon separates one statement from the next. The statement before an end does not need one, but it does no harm, and adding the next line is easier when it is there:

program Three;

{$mode objfpc}{$H+}

begin
  WriteLn('one');
  WriteLn('two');
  WriteLn('three');
end.

one
two
three

#Writing more than text

WriteLn writes several things one after the other, separated by commas. Write does the same without ending the line:

program Sums;

{$mode objfpc}{$H+}

begin
  WriteLn('2 + 3 = ', 2 + 3);
  Write('Ten times twelve is ');
  WriteLn(10 * 12, '.');
  WriteLn;                         // an empty line
  WriteLn('Done.');
end.

2 + 3 = 5
Ten times twelve is 120.

Done.

#Reading what the user types

ReadLn waits until the user types a line and presses Enter. To keep what was typed you need a variable, a named place for a value. Variables are declared in a var section before begin — chapter 2 explains them; here is a first one:

program Greet;

{$mode objfpc}{$H+}

var
  Name: string;
begin
  Write('What is your name? ');
  ReadLn(Name);
  WriteLn('Hello, ', Name, '!');
end.

When the user types Ayşe:

Ayşe

What is your name? Hello, Ayşe!

(On the screen the answer appears after the question, where it was typed.)

#Comments

The compiler skips comments. Pascal has three kinds:

{ curly braces: one line or many }
(* round brackets and stars: the same; useful around code that has { } in it *)
// two slashes: until the end of the line

Write comments that say why, not what: Inc(Total, Price) needs no comment, but the reason an unusual line is there does.

#When something is wrong

Make a mistake on purpose: delete the semicolon after WriteLn('one') in the program Three and run it.

src/main.pas(7,3) Fatal: Syntax error, ";" expected but "identifier WRITELN" found

The compiler gives the file, the line and column (7,3), and what it expected. It found the problem at the start of line 7 — the place right after the missing semicolon. Messages often point just after the real mistake: look at the line before, too. In VS Code the mistake is underlined as you type, and Problems (Ctrl+Shift+M) lists them all.

#Building without running

pastel build              # a debug build: build/linux/debug/hello (hello.exe on Windows)
pastel build --release    # an optimized, smaller one: build/linux/release/hello

A debug build carries what the debugger needs and checks more (an array index outside the array stops the program with a message). A release build is what you give to others. Both are a single file: copy it to another computer of the same kind and it runs.

pastel build --target windows makes the Windows program on Linux, too; pastel targets lists the platforms.

#Exercises

  1. Write a program that prints your name, then on the next line the year you were born.
  2. Write It's done. on the screen. (Hint: the quote.)
  3. Ask for two words with two ReadLns, then write them in the other order.
  4. ★ Remove end. at the end of a program. Read the error. Then write end; instead of end. What does the compiler say now?
