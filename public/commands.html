#The pastel command

Everything Pastel does from the terminal, with examples. pastel help shows the short list; every command works in any folder of a project (it finds pastel.toml). Exit codes: 0 worked, 1 failed (compile errors, failing tests...), 2 wrong usage.

Projects: new · upgrade · clean Packages: add · remove · update · search · deps Building and running: build · run · test · fmt · check Shipping: package · logcat · keystore · java · targets · doctor · setup Apps: lang · preview · schema Services: migrate Other: version · help

#pastel new

Creates a project, or adds a form, a control or a model (a table) to it.

pastel new console hello        # a command-line program
pastel new app notes            # a desktop app with a window (src/forms/Home.pform)
pastel new service watcher      # a program that keeps running (systemd)
pastel new api shop             # a web API with a database, models, migrations and tests
pastel new site shop-site       # a web site: pages from templates (pages.md), Bootstrap, a contact form
pastel new lib text-tools       # units for other projects (no program of its own)

pastel new form Settings        # in an app: src/forms/Settings.pform/.pas, added to main.pas
pastel new app shop --phone     # an app for phones (android.md): stacked, finger-sized controls
pastel new form Details --phone # a form for phones
pastel new frame Address        # a part of forms: src/frames/Address.pform/.pas (object Billing: TAddressFrame)
pastel new group                # the projects of the folders here as a group (build, test, run them together; workflow.md)
pastel new control StarRating   # in an app or lib: src/controls/starrating.pas
pastel new model Customer name:string! email:string age:integer
                                # a table: its migration, src/models/customers.pas and tests

Forms exist only in app projects: pastel new form in a console program, a service or an API stops and says so — a window there would never be shown. Make the window part as an app that uses the project (pastel add <project> --path ../<project>). Controls (pastel new control) belong to apps and libraries.

In VS Code, Pastel: New Project… does the same as pastel new with a wizard: the kind of project, its name, its folder and its platforms.

The kinds are explained in getting-started.md; forms in forms.md, controls in components.md, models in database.md.

#pastel build

Compiles the project into build/<platform>/<debug|release>/.

pastel build                     # debug build for this computer
pastel build --release           # optimized, without debug information (-r)
pastel build --target windows    # for another platform (-t); see pastel targets
pastel build --all               # every platform in [targets] platforms
pastel build --target linux,windows   # these platforms
pastel build -v                  # show the compiler's command and every message

Before compiling, .pform files are checked and turned into code, and assets/ is compiled in (release builds). Compiler errors show the file and line, relative to the project.

#pastel run

Builds and starts the program on this computer.

pastel run
pastel run -- --verbose input.txt      # arguments after -- go to the program
pastel run --watch                     # build and start again on every saved file
pastel run --release

While a desktop app runs, saving a .pform file updates the window at once (hot reload).

pastel run --target android            # on the phone connected with USB: installs, starts, shows its log

See android.md.

#pastel test

Runs the tests in tests/ (units with TTestSuite classes, see testing.md).

pastel test                  # all
pastel test money            # only tests whose name contains "money"
pastel test --watch          # again on every saved file
pastel test --json           # results as JSON (for editors and CI)

#pastel fmt

Formats Pascal code in one standard style (workflow.md).

pastel fmt                   # every .pas file of the project
pastel fmt src/forms         # only these files or folders
pastel fmt --check           # only report; exit code 1 when something is not formatted (CI)
pastel fmt --stdin < a.pas   # read code, write it formatted (editors)

#pastel check

Finds mistakes without a full build: in .pform files (unknown controls and properties, wrong values, missing event handlers, a form named like the program's file: Main.pform next to main.pas), or in a .pas file (compiler errors).

pastel check                                  # every .pform of the project
pastel check src/forms/Home.pform
pastel check src/forms/Home.pas --json        # compiler errors as JSON
cat Home.pform | pastel check src/forms/Home.pform --stdin --json    # unsaved text (editors)

#pastel package

A release build, packed to hand out (deploy.md, guide-desktop.md).

pastel package                          # dist/<name>-<version>-linux.tar.gz (Windows: .zip)
pastel package --target windows         # a .zip with the .exe and its DLLs
pastel package --all                    # every platform in pastel.toml
pastel package --target linux,windows   # these platforms
pastel package deb                      # a Debian/Ubuntu package (service: with systemd unit; app: menu entry)
pastel package docker                   # a container image (services)
pastel package appimage                 # one file that runs on most Linux systems (apps)
pastel package installer --target windows   # a Windows installer (needs makensis)
pastel package apk                      # an Android app, signed: dist/<name>-<version>.apk, for every
                                        # Android CPU set up (android.md); --target android-arm: one
pastel package aab                      # Google Play's bundle (.aab), signed with [package.android] keystore
pastel package --no-build               # pack what was built already

Next to every archive is a .sha256 file. What goes in: the program, README, LICENSE and [package] include from pastel.toml.

#pastel logcat

The log of the app on the connected Android phone, TV box or emulator, by the app's package name ([package.android] id): the lines of its processes, when it starts and dies, and crash reports — with the Pascal function and line of a crash, from the debug build. pastel run --target android shows the same after starting the app.

pastel logcat              # until Ctrl+C; start the app on the phone, its lines show here
pastel logcat --clear      # forget the older lines first
pastel logcat --all        # every line of the phone, not only the app's

The whole log goes to build/android/logcat.txt too, to send with a question (android.md).

#pastel keystore

An Android app's release key, once per app: Google Play knows an app by it, and every update must be signed with the same one. It is made with Java's keytool into keys/upload.keystore; [package.android] keystore and alias go into pastel.toml, and keys/ into .gitignore.

pastel keystore                                   # asks for a password twice
PASTEL_KEYSTORE_PASSWORD=... pastel package aab   # signed with it, for Google Play

Keep the file and its password safe (a copy outside the computer): a lost key means a new app in Google Play.

#pastel update-manifest

dist/update.json for apps that update themselves (Pastel.Updater, system.md): the project's version and, for each platform, its package in dist/ (the setup .exe, the .AppImage, the .apk) with the address it will have and its SHA-256.

pastel package installer --target windows && pastel package appimage && pastel package apk
pastel update-manifest https://example.com/shop/ "Faster sync"     # then put dist/update.json and the packages there

#pastel java

Java classes as typed Pascal (java.md): Android's (from android.jar), the project's own (src/java), a library's ([java] jars). The list is [java] classes in pastel.toml; the unit is src/java/javaclasses.pas.

pastel java search Notification          # the classes with these words in their names
pastel java add android.widget.Toast     # added to the list; the unit is written again
pastel java remove android.widget.Toast
pastel java                              # the unit written again (after a change of src/java)

#pastel targets

Lists the platforms Pastel can build for and their short names (windows, rpi, linux-arm64, android-arm...).

pastel targets

#pastel doctor

Checks the setup: the compiler, the libraries apps and HTTPS need, and which platforms can be built.

pastel doctor
pastel doctor --install windows    # set up building for Windows on Linux: Free Pascal's units
                                   # for Windows (from fpc-source) and SDL2.dll / freetype.dll
pastel doctor --install android    # set up building for Android, without the NDK: every CPU whose
                                   # binutils are installed (ARM 64/32-bit, x86_64, x86); the
                                   # ARM 32-bit and x86 compilers are built from fpc-source (android.md)
pastel doctor --install android-arm   # one of them

#pastel setup

Sets up making Android apps and says what is ready: what pastel doctor --install android does, then Android's tools one by one — Java, the SDK, its platform and build tools, adb and the phones connected, bundletool (downloaded) — and which commands work (package apk, run --target android, package aab, java add).

pastel setup android
pastel setup android --yes    # also the SDK's missing packages (Android 16's platform, build tools 36,
                              # platform-tools) with Android's sdkmanager, accepting Android's licenses;
                              # no sdkmanager (Ubuntu's packages): Google's, into ~/Android/Sdk

#pastel lang

Collects the texts of an app for translation into assets/lang/<code>.json (guide-desktop.md).

pastel lang add tr       # a new language: assets/lang/tr.json with every text
pastel lang              # update every language file; tells what is not translated yet
pastel lang list         # the texts that would be translated

#pastel migrate

Runs database migrations from database/migrations/ (database.md).

pastel migrate                          # run what did not run yet
pastel migrate status                   # applied / pending
pastel migrate new add_customers        # a new file: database/migrations/002_add_customers.sql
pastel migrate --database postgres://user:pw@localhost/shop

#pastel add

Adds a package to [dependencies] and pastel.lock, and fetches it (packages.md).

pastel add serial                                    # from the registry, the newest version
pastel add serial@^1.0                               # a range of versions
pastel add chart --git https://github.com/someone/pastel-chart
pastel add gpio --git https://github.com/azrov/pastel-extras --path gpio --branch main
pastel add salon-core --path ../salon-core           # a folder on this computer

#pastel remove

Removes packages from pastel.toml, and from pastel.lock what nothing needs any more.

pastel remove serial

#pastel update

Moves packages to the newest version pastel.toml allows and writes pastel.lock.

pastel update               # all
pastel update serial        # one

#pastel search

Looks for packages in the registry, by name and description.

pastel search               # every package
pastel search barcode

#pastel deps

The dependencies, theirs, and the versions used.

pastel deps
pastel deps --json          # for editors: name, version, folder

#pastel upgrade

Brings a project made with an older Pastel up to date (project.md).

pastel upgrade --check     # only tell what would change (exit code 1 if anything)
pastel upgrade

#pastel clean

Deletes build/.

pastel clean

#pastel preview

Draws a form into a PNG without running the app — for documentation, reviews, or a quick look.

pastel preview src/forms/Home.pform -o home.png
pastel preview src/forms/Home.pform -o home-dark.png --dark
pastel preview src/forms/Home.pform -o home-android.png --style material

It draws the form in the app's style and colors (assets/theme.toml, assets/styles/); --style chooses another one (styles).

#pastel schema

Prints every control and component with its properties as JSON. Editors (the VS Code designer) use it; with controls of the project or its libraries, it includes them.

pastel schema > controls.json

#pastel version

pastel version        # pastel 1.0.0

#pastel help

pastel help           # also: pastel --help
